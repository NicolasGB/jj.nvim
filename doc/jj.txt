INTRODUCTION                                    *jj*

Plugin that helps work with Jujutsu <https://www.jj-vcs.dev/latest/> repositories

COMMANDS                                        *jj-commands*

                                                *jj-:J*
:J                      With no arguments, runs :J log

                                                *:J*
:J {args}               Runs one of the jj-nvim subcommands

                                                *:J_describe*
:J desc[ribe]           Set change descriptions with a Git-style commit message editor

                                                *:J_status*
:J st[atus]             Show repository status

                                                *:J_log*
:J log                  Display log history with configurable options and change the displayed revset from the log buffer

                                                *:J_diff*
:J diff                 Show changes with optional filtering by current file

                                                *:J_new*
:J new                  Create a new change with optional parent selection

                                                *:J_edit*
:J edit                 Edit a change

                                                *:J_squash*
:J squash               Squash the current diff to its parent or interactive squash mode from the log buffer

                                                *:J_split*
:J split                Split a change interactively in a floating terminal

                                                *:J_resolve*
:J resolve              Resolve conflicts interactively in a floating terminal or via external strategy

                                                *:J_rebase*
:J rebase               Rebase changes to a destination

                                                *:J_duplicate*
:J duplicate            Duplicate one or more changes to a destination revision

                                                *:J_bookmark_create*
:J bookmark create      Create bookmarks

                                                *:J_bookmark_delete*
:J bookmark delete      Delete bookmarks

                                                *:J_bookmark_track*
:J bookmark track       Track bookmarks

                                                *:J_bookmark_forget*
:J bookmark forget      Forget bookmarks

                                                *:J_tag_set*
:J tag set              Set tags

                                                *:J_tag_delete*
:J tag delete           Delete tags

                                                *:J_tag_push*
:J tag push             Push tags (Requires colocated repo)

                                                *:J_undo*
:J undo                 Undo the last operation

                                                *:J_redo*
:J redo                 Redo the last undone operation

                                                *:J_open_pr*
:J open_pr              Open a PR/MR on your remote (GitHub, GitLab, Gitea, Forgejo, etc.)

                                                *:J_browse*
:J browse [revision]    Open the current file on your remote at the current line (or selected range). Defaults to @

                                                *:J_annotate*
:J annotate             View file blame line history with change ID, author, and timestamp

                                                *:J_annotate_line*
:J annotate_line        View line history with change ID, author, and timestamp

                                                *:J_commit*
:J commit               Describe the current change and create a new one after

                                                *:J_diff_history*
:J diff_history         Open a history-aware diff between two revisions when supported by your diff backend

                                                *:Jdiff*
:Jdiff [revision]
:Jvdiff [revision]      Vertical split diff against a jj revision. Defaults to @

                                                *:Jhdiff*
:Jhdiff [revision]      Horizontal split diff

MAPS                                           *jj-maps*

                                               *jj-log-maps*
Log maps ~
<SHIFT-K>               Show a tooltip with the revision's changed files.
                        Press a second time to enter the tooltip buffer.

<CR>                    Edit the revision and open the file

<SHIFT-CR>              Edit the revision and open the file ignoring immutability

<SHIFT-D>               You can diff any change in your log history by pressing
                        `<SHIFT-D>` on its line or on a summary file change. This opens the configured
                        diff backend for the revision under the cursor.

                        This integrates with your preferred diff plugin or uses your native jj diff config.
                        See |jj-diff-module|

<CTRL-R>                Prompt for a new revset and reload the log buffer with it

d                       Describe the revision under cursor

n                       Create a new change branching off the revision under the cursor

<CTRL-N>                Create a new change after the revision under the cursor

<SHIFT-N>               Create a new change after the revision under the cursor ignoring immutability

<SHIFT-U>               Undo the last operation

<SHIFT-R>               Redo the last operation

a                       Abandon the revision under the cursor

f                       Fetch from remote

<SHIFT-P>               Push a bookmark through the picker

p                       Push bookmark of revision under cursor to remote

b                       Create a new bookmark or move an existing one to the
                        revision under cursor.

                        Select from existing bookmarks to move them or create
                        a new bookmark at that revision

B                       Delete a bookmark at the revision uder cursor.
                        If multiple bookmarks are present, select from the
                        list or delete all of them

<SHIFT-T>               Create a new tag on the revision under cursor

s                       Enter standard squash mode for the revison(s) under cursor

is                      Enter interactive squash mode for the revision(s) under cursor

<SHIFT-S>               Immediately squash the revision under cursor into its parent

<SHIFT-I> <SHIFT-S>     Interactively squash the revision under the cursor into its parent

<CTRL-S>                Split the revision under cursor

gr                      Resolve conflicts for the selected revision
                        See |jj-resolve-module|

r                       Enter |jj-rebase-mode| targeting the revision(s) under cursor
                        See |jj-rebase-module|

<CTRL-Y>                Enter |jj-duplicate-mode| targeting the revision(s) under cursor
                        See |jj-diff-module|

o                       Open a PR/MR from the revision under cursor

<SHIFT-O>               Select a remote from all available bookmarks are open a PR/MR
                        See |jj-pr-module|

DIFF MODULE                                    *jj-diff-module*

The diff module provides a unified API for viewing diffs with pluggable backend support.

The natively supported backends are:

- Native (Diffs the current file in place and uses a floating buffer with your jj diff command when diffing changes)
- CodeDiff <https://github.com/esmuellert/codediff.nvim>
- Diffview <https://github.com/sindrets/diffview.nvim>

RESOLVE MODULE                                 *jj-resolve-module*

How it integrates with the log buffer:

- Uses `jj resolve --revision <revset>` for the revision under cursor
- If `cmd.resolve_strategies` has more than one strategy, `vim.ui.select` prompts you to choose one
- If a strategy is selected, its `args` and `external` options are passed to `cmd.resolve(...)`
- On success, the log buffer is automatically reloaded so conflict state is refreshed
- When using floating terminals, cancelled/failed resolve attempts restore the log view

REBASE MODULE                                  *jj-rebase-module*

Once in rebase mode, the interface highlights your selection and the current rebase destination:

- Selected changes are highlighted in your configured `selected_hl` color (default: dark magenta)
- The cursor position (potential rebase destination) is highlighted in your configured `targeted_hl` color (default: green)
- Move the cursor to preview different rebase destinations with live highlighting

DUPLICATE MODULE                               *jj-duplicate-module*

Once in duplicate mode, the interface highlights your selection and the current duplicate destination:

- Selected changes are highlighted in your configured `selected_hl` color (default: dark magenta)
- The cursor position (target destination) is highlighted in your configured `targeted_hl` color (default: green)
- Move the cursor to preview different duplicate destinations with live highlighting

PR MODULE                                      *jj-pr-module*

This is a jj.nvim exclusive feature - The ability to seamlessly bridge from your Neovim jj workflow directly
to your remote platform's PR/MR interface.

- Extracts the bookmark from the revision
- Detects your git platform (GitHub, GitLab, Gitea, Forgejo, etc.)
- Constructs the appropriate PR/MR URL
- Handles both HTTPS and SSH remote URLs
- Prompts you to select a remote if you have multiple

BROWSE MODULE                                  *jj-browse-module*

Open the current buffer's file in your browser on the hosted remote (GitHub/GitLab/Gitea/Forgejo, etc.) at
the current cursor line or a visually selected range.

- Takes the current buffer path and makes it repo-relative (must be inside a jj repo)
- Collects git remotes; if there's more than one, prompts you to pick one
- Normalizes the remote URL to an HTTPS base repo URL
- Picks a ref that is expected to exist on the remote:
  - With default `@`: walks back first-parent up to 20 parents to find a commit reachable from that remote's bookmarks; falls back to `trunk()` if needed
  - With an explicit revset (e.g. `main`, `@-2`): uses that revset directly (no walkback)
  - If there's a single unambiguous remote bookmark pointing at the chosen commit, uses that bookmark name; otherwise uses the commit SHA
- Builds a provider-specific URL and adds a line anchor:
  - GitHub-style: `#L<start>` or `#L<start>-L<end>`
  - GitLab-style: `#L<start>` or `#L<start>-<end>`
